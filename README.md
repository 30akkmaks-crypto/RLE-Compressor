RLE Compressor – Утилита сжатия текста (RLE) на 7 языках
Эффективное сжатие повторяющихся последовательностей с помощью алгоритма Run-Length Encoding (RLE).
Поддерживает любые тексты, включая цифры и специальные символы, используя escape-последовательности.
Реализовано на семи языках программирования с единым интерфейсом командной строки.

🚀 Возможности
Сжатие – заменяет серии из 3 и более одинаковых символов на пару (символ + количество).

Распаковка – восстанавливает исходный текст из сжатого формата.

Escape-символ – \ используется для экранирования управляющих последовательностей.

Поддержка файлов – работа с текстовыми файлами любого размера.

Гибкий ввод/вывод – можно указать входной/выходной файл или использовать стандартные потоки.

Цветной вывод – информативные сообщения об успехе/ошибке.

📖 Использование
Синтаксис (единый для всех версий):

bash
<команда> <режим> <входной_файл> [выходной_файл]
Режимы
compress – сжать файл.

decompress – распаковать файл.

Если выходной файл не указан, результат выводится в стандартный вывод (stdout).
Если входной файл не указан (или указан -), чтение происходит из stdin.

Примеры
bash
# Сжатие файла
python rle.py compress input.txt output.rle

# Распаковка
python rle.py decompress output.rle restored.txt

# Сжатие из stdin в stdout
cat input.txt | python rle.py compress - > compressed.rle

# Справка
python rle.py -h

🧠 Алгоритм RLE
Сжатие:
Проходит по тексту и подсчитывает длину каждой серии одинаковых символов.
Если длина серии ≥ 3, она заменяется на: символ + '\' + число_повторов.
Если длина серии меньше 3, символы остаются как есть (но символ \ дублируется).
Например: AAAABBBCC → A\4B\3CC

Распаковка:
Сканирует сжатый текст. При встрече \ считывает следующий символ и число, затем повторяет символ указанное количество раз.
Если встречается \\ – это означает обычный символ \.

Преимущества:

Работает с любыми текстами (включая цифры).

Эффективно сжимает длинные повторения.

Прост в реализации и понимании.

✨ Дополнительные фичи
Автоматическое определение режима – если указан только один аргумент, считается, что это входной файл, а выход – stdout.

Обработка ошибок – проверка корректности сжатых данных при распаковке.

Цветной вывод – сообщения об успехе/ошибке выделяются цветом (в терминалах с поддержкой ANSI).
